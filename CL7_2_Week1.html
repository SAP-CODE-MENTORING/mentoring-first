이 페이지의 가정

ET_FLIGHTS는 BC400_T_FLIGHTS, 한 줄은 BC400_S_FLIGHT이고 칸 순서는 CARRID · CONNID · FLDATE · SEATSMAX · SEATSOCC · PERCENTAGE라고 가정했어요. 내 Structure의 칸 순서나 이름이 다르면 코드도 거기에 맞춰 바꾸세요.

원본 모범 답안 보기
Exercise 18 모범 답안 (요약)
FUNCTION Z_BC400_G##_FLIGHTLIST_GET_OPT.

  DATA LS_FLIGHT LIKE LINE OF ET_FLIGHTS.

  " SELECT 반복문(Exercise 17)은 주석으로 남겨 둠 (생략)

  SELECT
    CARRID,
    CONNID,
    FLDATE,
    SEATSMAX,
    SEATSOCC
  FROM SFLIGHT
  INTO TABLE @ET_FLIGHTS
  WHERE CARRID EQ @IV_CARRID
    AND CONNID EQ @IV_CONNID.

  " 읽은 데이터가 없으면 Exception 발생
  IF SY-SUBRC NE 0.
    RAISE NO_DATA.
  ENDIF.

  " 반복문으로 좌석 이용률 계산
  LOOP AT ET_FLIGHTS INTO LS_FLIGHT.
    LS_FLIGHT-PERCENTAGE = 100 * LS_FLIGHT-SEATSOCC / LS_FLIGHT-SEATSMAX.
    MODIFY ET_FLIGHTS FROM LS_FLIGHT INDEX SY-TABIX TRANSPORTING PERCENTAGE.
  ENDLOOP.

  SORT ET_FLIGHTS BY PERCENTAGE DESCENDING.

ENDFUNCTION.

핵심은 세 가지예요. ① INTO TABLE로 한 번에 채우고 ② 바로 뒤에서 SY-SUBRC로 NO_DATA를 판단하고 ③ SORT는 이용률을 다 계산한 ENDLOOP 뒤에 둬요.

짚고 갈 것 SY-SUBRC는 바로 앞 문장의 결과예요. SORT 뒤에서 확인해도 우연히 맞을 때가 있지만, SELECT 바로 뒤에서 확인해야 “SELECT가 데이터를 읽었는지”를 정확히 볼 수 있어요.

복습 1 프로그램에서 FM 불러 쓰기 ★☆☆

요청서운항관리팀 · 조회 화면
Function Module은 다 만들어졌다고 들었어요. 그런데 저희는 SE37 테스트 화면 말고 프로그램을 실행해서 보고 싶어요. 항공사와 노선 번호를 넣으면 일정 목록이 나오게 해 주세요. 없는 노선이면 데이터가 없다고 알려 주세요.

힌트

힌트 1

Exercise 9 계산기에서 Z_BC400_G##_COMP_PERCENTAGE를 불렀던 것처럼 Pattern 버튼으로 CALL FUNCTION 문장을 넣으세요.

힌트 2

FM이 돌려주는 ET_FLIGHTS를 받을 변수가 필요해요. Exercise 14에서 GT_CONNECTION TYPE BC400_T_CONNECTIONS로 선언했던 것처럼 BC400_T_FLIGHTS 타입으로 만들고, 한 줄 변수는 LIKE LINE OF로 만드세요.

힌트 3

예외 처리는 계산기처럼 CALL FUNCTION 바로 뒤에서 CASE SY-SUBRC로 해요. 0일 때만 LOOP AT … INTO …로 한 줄씩 WRITE 하세요.

확인할 것

모범 답안 보기
REPORT ZBC400_G##_FLIGHT_LIST.

PARAMETERS: PA_CAR TYPE BC400_S_FLIGHT-CARRID,
            PA_CON TYPE BC400_S_FLIGHT-CONNID.

DATA: GT_FLIGHTS TYPE BC400_T_FLIGHTS,
      GS_FLIGHT  LIKE LINE OF GT_FLIGHTS.

START-OF-SELECTION.

  CALL FUNCTION 'Z_BC400_G##_FLIGHTLIST_GET_OPT'
    EXPORTING
      IV_CARRID  = PA_CAR
      IV_CONNID  = PA_CON
    IMPORTING
      ET_FLIGHTS = GT_FLIGHTS
    EXCEPTIONS
      NO_DATA    = 1
      OTHERS     = 2.

  CASE SY-SUBRC.
    WHEN 0.
      LOOP AT GT_FLIGHTS INTO GS_FLIGHT.
        WRITE: / GS_FLIGHT-CARRID,
                 GS_FLIGHT-CONNID,
                 GS_FLIGHT-FLDATE,
                 GS_FLIGHT-SEATSMAX,
                 GS_FLIGHT-SEATSOCC,
                 GS_FLIGHT-PERCENTAGE.
      ENDLOOP.
    WHEN 1.
      WRITE / '조회된 데이터가 없습니다.'.
    WHEN OTHERS.
      WRITE / '알 수 없는 오류가 발생했습니다.'.
  ENDCASE.

생각해 볼 것 FM에서는 IV_CARRID가 Import인데, CALL FUNCTION에서는 EXPORTING 아래에 적어요. ET_FLIGHTS는 반대로 IMPORTING 아래에 있고요. 왜 반대인지 “누가 보내고 누가 받는지”로 짝지어 보세요.

힌트

힌트 1

요청서에서 바뀌는 것만 골라 보세요. 입력(IV_CONNID 빠지고 날짜 둘 추가), WHERE 조건, 예외 하나 추가, 정렬 기준. 나머지(INTO TABLE, LOOP, MODIFY)는 원본 그대로예요.

힌트 2

기간 조건은 “시작일보다 크거나 같고(GE) 종료일보다 작거나 같다(LE)”를 AND로 이어서 써요. 날짜 검사는 COMP_PERCENTAGE에 적어 둔 “1. 입력값 점검”처럼 SELECT보다 먼저 하세요. 잘못된 입력이면 굳이 읽을 필요가 없으니까요.

힌트 3

정렬 기준이 두 개면 SORT itab BY 칸1 칸2.처럼 나란히 적어요. 앞에 적은 칸이 먼저 기준이 돼요.

확인할 것

모범 답안 보기
FUNCTION Z_BC400_G##_FLIGHTLIST_PERIOD.

  DATA LS_FLIGHT LIKE LINE OF ET_FLIGHTS.

  " 1. 입력값 점검
  IF IV_DATE_FROM > IV_DATE_TO.
    RAISE WRONG_PERIOD.
  ENDIF.

  " 2. 로직 처리
  SELECT
    CARRID,
    CONNID,
    FLDATE,
    SEATSMAX,
    SEATSOCC
  FROM SFLIGHT
  INTO TABLE @ET_FLIGHTS
  WHERE CARRID EQ @IV_CARRID
    AND FLDATE GE @IV_DATE_FROM
    AND FLDATE LE @IV_DATE_TO.

  IF SY-SUBRC NE 0.
    RAISE NO_DATA.
  ENDIF.

  LOOP AT ET_FLIGHTS INTO LS_FLIGHT.
    LS_FLIGHT-PERCENTAGE = 100 * LS_FLIGHT-SEATSOCC / LS_FLIGHT-SEATSMAX.
    MODIFY ET_FLIGHTS FROM LS_FLIGHT INDEX SY-TABIX TRANSPORTING PERCENTAGE.
  ENDLOOP.

  " 3. 결과값 전달: 노선별, 날짜 순
  SORT ET_FLIGHTS BY CONNID FLDATE.

ENDFUNCTION.

생각해 볼 것 시작일과 종료일을 같은 날로 넣으면 그날 일정이 나오나요? GE, LE 대신 GT, LT를 쓰면 결과가 어떻게 달라질지도 생각해 보세요.

복습 3 조건 골라서 노선 찾기 ★★☆

요청서여행사 · 상품 기획용
항공사 여러 개와 출발 도시를 골라서 노선을 보고 싶어요. 아무것도 안 넣으면 전부 보여 주세요. 비행시간은 분 말고 시간(예: 1.5시간)으로 보여 주시고, 오래 걸리는 노선부터 나오면 좋겠어요.

ZBC400_G##_CONN_SEARCH (Executable Program, SE38)
입력
SO_CAR (항공사, SELECT-OPTIONS), SO_CFR (출발 도시, SELECT-OPTIONS)

힌트

힌트 1

결과 한 줄에는 SPFLI에 없는 비행시간(시간) 칸이 하나 더 있어야 해요. HW-2C에서 잔여좌석·예약률 칸을 추가했던 것처럼 TYPES: BEGIN OF … END OF로 만들고, Table Type은 TT_로 시작하게 선언하세요.

힌트 2

SELECT-OPTIONS는 FOR 뒤에 변수가 와야 해요. 그래서 Structure 변수를 먼저 선언하고 FOR GS_CONN-CARRID처럼 그 칸을 쓰세요. WHERE에서는 = 대신 IN으로 비교하고, 비워 두면 전체가 조회돼요.

힌트 3

결과 Structure는 칸 순서가 SELECT와 달라요(FLHOUR가 중간에 있음). 이름이 같은 칸끼리 맞춰 넣으려면 HW-2C처럼 INTO CORRESPONDING FIELDS OF TABLE을 쓰세요. 분을 시간으로 바꾸는 건 LOOP에서 FLTIME / 60.

확인할 것

모범 답안 보기
REPORT ZBC400_G##_CONN_SEARCH.

" 1. 결과 한 줄 모양: SPFLI 칸 5개 + 직접 계산하는 칸 1개(FLHOUR)
TYPES: BEGIN OF TS_CONN,
         CARRID   TYPE SPFLI-CARRID,
         CONNID   TYPE SPFLI-CONNID,
         CITYFROM TYPE SPFLI-CITYFROM,
         CITYTO   TYPE SPFLI-CITYTO,
         FLHOUR   TYPE P LENGTH 5 DECIMALS 1,  " 비행시간(시간)
         FLTIME   TYPE SPFLI-FLTIME,           " 비행시간(분)
       END OF TS_CONN.

TYPES TT_CONN TYPE STANDARD TABLE OF TS_CONN
              WITH NON-UNIQUE KEY CARRID CONNID.

DATA: GT_CONN TYPE TT_CONN,
      GS_CONN TYPE TS_CONN.

" 2. 입력 화면: FOR 뒤에는 변수(의 칸)가 와야 함
SELECT-OPTIONS: SO_CAR FOR GS_CONN-CARRID,
                SO_CFR FOR GS_CONN-CITYFROM.

" 3. 조회: FLHOUR 때문에 칸 순서가 달라서 이름으로 맞춰 넣음
SELECT
    CARRID,
    CONNID,
    CITYFROM,
    CITYTO,
    FLTIME
FROM SPFLI
INTO CORRESPONDING FIELDS OF TABLE @GT_CONN
WHERE CARRID IN @SO_CAR
  AND CITYFROM IN @SO_CFR.

IF SY-SUBRC NE 0.
  WRITE TEXT-E01. " 조회된 노선이 없습니다.
  RETURN.
ENDIF.

" 4. 분 → 시간
LOOP AT GT_CONN INTO GS_CONN.
  GS_CONN-FLHOUR = GS_CONN-FLTIME / 60.
  MODIFY GT_CONN FROM GS_CONN.
ENDLOOP.

SORT GT_CONN BY FLHOUR DESCENDING.

" 5. 출력
LOOP AT GT_CONN INTO GS_CONN.
  WRITE: /(6)  GS_CONN-CARRID   COLOR COL_KEY,
          (6)  GS_CONN-CONNID   COLOR COL_KEY,
          (20) GS_CONN-CITYFROM,
          (20) GS_CONN-CITYTO,
          (8)  GS_CONN-FLHOUR.
ENDLOOP.

생각해 볼 것 INTO CORRESPONDING FIELDS OF TABLE을 그냥 INTO TABLE로 바꾸면 어떻게 될까요? 다섯 번째 칸(FLTIME, 분)이 Structure의 다섯 번째 칸인 FLHOUR에 들어가요. 복습 5의 “순서대로 들어간다”와 같은 이야기예요. 디버거로 확인해 보세요.

FUNCTION Z_BC400_G##_FLIGHTLIST_FULL.

  DATA LS_FLIGHT LIKE LINE OF ET_FLIGHTS.

  CLEAR ET_FLIGHTS[].

  " Exercise 17처럼 SELECT 반복문으로 한 줄씩 읽음
  SELECT
    CARRID,
    CONNID,
    FLDATE,
    SEATSMAX,
    SEATSOCC
  FROM SFLIGHT
  INTO @LS_FLIGHT

    AND CONNID EQ @IV_CONNID.

    LS_FLIGHT-PERCENTAGE = 100 * LS_FLIGHT-SEATSOCC / LS_FLIGHT-SEATSMAX.

    IF LS_FLIGHT-PERCENTAGE GE IV_MIN_PERCENT.
      APPEND LS_FLIGHT TO ET_FLIGHTS.

복습 5 고장 난 Function Module 고치기 ★★☆

요청서운영 문의 · 현업 3건 접수
  1. “이용률이 150%로 나오는 일정이 있어요. 날짜를 바꾸면 가끔 덤프도 나요.”
  2. “이용률 높은 순으로 보여 준다고 했는데 순서가 뒤죽박죽이에요.”
  3. “없는 노선 번호를 넣었는데 아무 메시지 없이 빈 결과만 나와요.”

원본 FM을 Z_BC400_G##_FLIGHTLIST_BUG로 복사한 뒤 소스를 아래 코드로 바꿔 넣고, 문의 3건의 원인을 찾아 고치세요. 디버거로 원인을 확인한 다음에 고치는 게 규칙이에요.

고장 난 코드
FUNCTION Z_BC400_G##_FLIGHTLIST_BUG.

  DATA LS_FLIGHT LIKE LINE OF ET_FLIGHTS.

  SELECT
    CARRID,
    CONNID,
    FLDATE,
    SEATSOCC,
    SEATSMAX
  FROM SFLIGHT
  INTO TABLE @ET_FLIGHTS
  WHERE CARRID EQ @IV_CARRID
    AND CONNID EQ @IV_CONNID.

  SORT ET_FLIGHTS BY PERCENTAGE DESCENDING.

  LOOP AT ET_FLIGHTS INTO LS_FLIGHT.
    LS_FLIGHT-PERCENTAGE = 100 * LS_FLIGHT-SEATSOCC / LS_FLIGHT-SEATSMAX.
    MODIFY ET_FLIGHTS FROM LS_FLIGHT INDEX SY-TABIX TRANSPORTING PERCENTAGE.
  ENDLOOP.

ENDFUNCTION.

힌트

힌트 1

문의 1: SELECT 바로 뒤에 Breakpoint를 걸고 ET_FLIGHTS의 첫 줄을 열어 보세요. SE16으로 본 SFLIGHT 같은 줄과 SEATSMAX, SEATSOCC 값이 같나요? INTO TABLE은 이름이 아니라 순서대로 들어가요. CONNECTION_GET 주석에 적어 둔 “N번째 필드에 넣는다”를 떠올려 보세요.

힌트 2

문의 2: SORT를 실행하는 순간 PERCENTAGE 칸에는 어떤 값이 들어 있을까요?

힌트 3

문의 3: 원본 코드와 나란히 놓고 비교해 보세요. 데이터가 없을 때 누가 NO_DATA를 일으켜야 하나요?

원인과 정답 보기
문의원인고치는 법
1. 150%·덤프SELECT의 칸 순서가 SEATSOCC, SEATSMAX로 바뀌어 있어서 두 값이 뒤바뀌어 들어감. 탑승 0명인 일정은 0으로 나누게 돼서 CX_SY_ZERODIVIDE 덤프Structure 순서대로 SEATSMAX, SEATSOCC
2. 정렬 안 됨이용률을 계산하기 전(모두 0일 때) SORT 해서 정렬한 효과가 없음SORT를 ENDLOOP 뒤로
3. 메시지 없음SELECT 뒤 SY-SUBRC 확인과 RAISE NO_DATA가 빠짐SELECT 바로 뒤에 IF SY-SUBRC NE 0. RAISE NO_DATA. ENDIF.

다 고치면 원본 모범 답안과 같은 코드가 돼요. 멘티에게는 1번이 제일 위험한 버그라는 걸 짚어 주세요. 덤프가 안 나는 날짜에서는 에러 없이 틀린 숫자만 조용히 나가니까요.

예시 만든 FM 모아서 쓰기

문제는 아니고, 지금까지 만든 Function Module을 실무 프로그램처럼 묶어 쓰면 어떤 모양이 되는지 보여 주는 예시예요. 원본, 복습 2, 복습 4에서 만든 FM 세 개를 한 프로그램에서 불러서, 항공사·노선·기간·기준을 넣으면 세 가지 결과가 한 화면에 나와요.

아직 안 배운 PERFORM/FORM, OBLIGATORY, DEFAULT, ULINE, SKIP도 들어 있어요. 실제 코드가 어떻게 생겼는지 미리 보는 거라 지금 다 이해하지 않아도 괜찮아요.

구성
Program
ZBC400_G##_FLIGHT_REPORT
입력
PA_CAR, PA_CON, PA_FROM, PA_TO, PA_PCT (기본값 90)
① SHOW_ALL
원본 FLIGHTLIST_GET_OPT · 노선 전체 일정
② SHOW_PERIOD
복습 2 FLIGHTLIST_PERIOD · 기간 일정
③ SHOW_FULL
복습 4 FLIGHTLIST_FULL · 만석 임박 일정
공통
WRITE_TITLE (블록 제목), WRITE_LIST (목록 출력)
FM 세 개를 쓰는 프로그램
REPORT ZBC400_G##_FLIGHT_REPORT.

*----------------------------------------------------------------------*
* 선택 화면
*----------------------------------------------------------------------*
PARAMETERS: PA_CAR  TYPE BC400_S_FLIGHT-CARRID OBLIGATORY,
            PA_CON  TYPE BC400_S_FLIGHT-CONNID OBLIGATORY,
            PA_FROM TYPE BC400_S_FLIGHT-FLDATE OBLIGATORY,
            PA_TO   TYPE BC400_S_FLIGHT-FLDATE OBLIGATORY,
            PA_PCT  TYPE BC400_S_FLIGHT-PERCENTAGE DEFAULT 90.

*----------------------------------------------------------------------*
* 메인: 무슨 일을 하는지 세 줄로 보임
*----------------------------------------------------------------------*
START-OF-SELECTION.

  PERFORM SHOW_ALL.
  PERFORM SHOW_PERIOD.
  PERFORM SHOW_FULL.

*----------------------------------------------------------------------*
* ① 노선 전체 일정 (원본 FM)
*----------------------------------------------------------------------*
FORM SHOW_ALL.

  DATA LT_FLIGHTS TYPE BC400_T_FLIGHTS.

  PERFORM WRITE_TITLE USING '① 노선 전체 일정'.

  CALL FUNCTION 'Z_BC400_G##_FLIGHTLIST_GET_OPT'
    EXPORTING
      IV_CARRID  = PA_CAR
      IV_CONNID  = PA_CON
    IMPORTING
      ET_FLIGHTS = LT_FLIGHTS
    EXCEPTIONS
      NO_DATA    = 1
      OTHERS     = 2.

  CASE SY-SUBRC.
    WHEN 0.
      PERFORM WRITE_LIST USING LT_FLIGHTS.
    WHEN 1.
      WRITE / '조회된 데이터가 없습니다.'.
    WHEN OTHERS.
      WRITE / '알 수 없는 오류가 발생했습니다.'.
  ENDCASE.

ENDFORM.

*----------------------------------------------------------------------*
* ② 기간 일정 (복습 2 FM) - 노선 번호는 넘기지 않음
*----------------------------------------------------------------------*
FORM SHOW_PERIOD.

  DATA LT_FLIGHTS TYPE BC400_T_FLIGHTS.

  PERFORM WRITE_TITLE USING '② 기간 일정'.

  CALL FUNCTION 'Z_BC400_G##_FLIGHTLIST_PERIOD'
    EXPORTING
      IV_CARRID    = PA_CAR
      IV_DATE_FROM = PA_FROM
      IV_DATE_TO   = PA_TO
    IMPORTING
      ET_FLIGHTS   = LT_FLIGHTS
    EXCEPTIONS
      NO_DATA      = 1
      WRONG_PERIOD = 2
      OTHERS       = 3.

  CASE SY-SUBRC.
    WHEN 0.
      PERFORM WRITE_LIST USING LT_FLIGHTS.
    WHEN 1.
      WRITE / '조회된 데이터가 없습니다.'.
    WHEN 2.
      WRITE / '시작일이 종료일보다 늦습니다.' COLOR COL_NEGATIVE.
    WHEN OTHERS.
      WRITE / '알 수 없는 오류가 발생했습니다.'.
  ENDCASE.

ENDFORM.

*----------------------------------------------------------------------*
* ③ 만석 임박 일정 (복습 4 FM)
*----------------------------------------------------------------------*
FORM SHOW_FULL.

  DATA LT_FLIGHTS TYPE BC400_T_FLIGHTS.

  PERFORM WRITE_TITLE USING '③ 만석 임박 일정'.

  CALL FUNCTION 'Z_BC400_G##_FLIGHTLIST_FULL'
    EXPORTING
      IV_CARRID      = PA_CAR
      IV_CONNID      = PA_CON
      IV_MIN_PERCENT = PA_PCT
    IMPORTING
      ET_FLIGHTS     = LT_FLIGHTS
    EXCEPTIONS
      NO_DATA        = 1
      NO_FULL_FLIGHT = 2
      OTHERS         = 3.

  CASE SY-SUBRC.
    WHEN 0.
      PERFORM WRITE_LIST USING LT_FLIGHTS.
    WHEN 1.
      WRITE / '조회된 데이터가 없습니다.'.
    WHEN 2.
      WRITE / '기준을 넘는 일정이 없습니다.'.
    WHEN OTHERS.
      WRITE / '알 수 없는 오류가 발생했습니다.'.
  ENDCASE.

ENDFORM.

*----------------------------------------------------------------------*
* 공통: 블록 제목
*----------------------------------------------------------------------*
FORM WRITE_TITLE USING PV_TITLE TYPE CSEQUENCE.

  SKIP.
  WRITE / PV_TITLE COLOR COL_HEADING.
  ULINE.

ENDFORM.

*----------------------------------------------------------------------*
* 공통: 일정 목록 출력 (세 블록이 같이 씀)
*----------------------------------------------------------------------*
FORM WRITE_LIST USING PT_FLIGHTS TYPE BC400_T_FLIGHTS.

  DATA LS_FLIGHT LIKE LINE OF PT_FLIGHTS.

  WRITE: /(6)  '항공사' COLOR COL_KEY,
          (6)  '노선'   COLOR COL_KEY,
          (10) '날짜'   COLOR COL_KEY,
          (8)  '좌석'   COLOR COL_KEY,
          (8)  '예약'   COLOR COL_KEY,
          (8)  '이용률' COLOR COL_KEY.

  LOOP AT PT_FLIGHTS INTO LS_FLIGHT.
    WRITE: /(6)  LS_FLIGHT-CARRID,
            (6)  LS_FLIGHT-CONNID,
            (10) LS_FLIGHT-FLDATE,
            (8)  LS_FLIGHT-SEATSMAX,
            (8)  LS_FLIGHT-SEATSOCC,
            (8)  LS_FLIGHT-PERCENTAGE.
  ENDLOOP.

ENDFORM.

코드에서 볼 것

  • PERFORM은 이 프로그램 안에서 쓰는 작은 FM이라고 보면 돼요. 코드 묶음에 이름(FORM … ENDFORM)을 붙여 두고 PERFORM 이름으로 불러요. 그래서 START-OF-SELECTION은 세 줄만 읽어도 프로그램이 뭘 하는지 보여요.
  • 같은 코드는 한 번만 써요. 목록 출력은 세 블록이 똑같아서 WRITE_LIST 하나로 만들고, 결과 테이블을 USING으로 넘겨요. 출력 칸을 바꾸고 싶으면 여기 한 곳만 고치면 돼요.
  • FM마다 넘기는 값이 달라요. ②는 노선 번호를 받지 않고 날짜 두 개를 받아요. 그래서 없는 노선(9999)을 넣어도 ②에는 그 항공사의 기간 일정이 나와요.
  • 예외는 CALL FUNCTION마다 바로 뒤에서 확인해요. 같은 SY-SUBRC = 2라도 ②에서는 WRONG_PERIOD, ③에서는 NO_FULL_FLIGHT예요. 번호의 뜻은 그 CALL FUNCTION의 EXCEPTIONS에 적은 대로 정해져요.
  • 블록마다 FORM이 따로라서 서로 영향을 주지 않아요. 결과 테이블 LT_FLIGHTS는 FORM 안에서 선언한 지역 변수라 FORM이 끝나면 사라지고, 다음 FORM에서는 새로 비어 있는 상태로 시작해요. ①에서 예외가 나도 ②, ③은 그대로 실행돼요.
  • 변수 이름 앞글자로 어디서 쓰는 변수인지 알 수 있어요. PA_ 선택 화면, LT_·LS_ FORM 안 지역 변수, PT_·PV_ FORM이 받는 값. 지금까지 쓴 GT_·GS_는 프로그램 전체에서 쓰는 변수예요.

  • 1시간일 때 원본 복습(10분) → 복습 1 같이 풀기(15분) → 복습 2 각자(20분) → 복습 5 다 같이 디버거 띄워 놓고(15분). 복습 3·4는 숙제.
  • 2시간일 때 위 순서에 복습 3(30분, SELECT-OPTIONS·변수 선언 복습)과 리뷰(20분)를 더하고, 복습 4만 숙제로.
  • 마무리 (5분) 마지막에 예시 화면을 띄워 놓고 “오늘 만든 FM이 실제로는 이렇게 쓰여요” 정도로만 보여 주세요. 직접 따라 치게 할 필요는 없고, PERFORM은 “나중에 배울 거고 이 프로그램 안의 작은 FM”이라고만 짚어 주세요. 입력을 9999, 시작일 > 종료일, 기준 100으로 바꿔 가며 블록마다 다른 메시지가 나오는 걸 보여 주면 좋아요.
  • 리뷰 때 물어볼 것 “이 줄 빼면 어떻게 돼?”, “SORT를 여기 두면?”, “SY-SUBRC는 지금 어떤 문장의 결과야?” 같은 질문 하나면 충분해요.
  • 빨리 끝낸 멘티에게 같은 코드에 조건을 하나만 더하세요. 예: 복습 1에 “이용률 90% 이상인 줄은 앞에 ICON_RED_LIGHT AS ICON”, 복습 2에 “마지막 줄에 전체 일정 수 출력(LOOP 안에서 변수에 1씩 더하기)”.
  • 테스트 값 SE16으로 SFLIGHT를 열어 실제로 있는 항공사·노선을 고르게 하세요. 항공사 코드는 대문자, 노선 번호는 네 자리(0400)로.
